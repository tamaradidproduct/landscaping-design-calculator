# Plan Builder: layering (2026-10-19)

## Decisions
- **Plants & objects is the top group by default**; the four Layers sections can be **moved up and down** (↑ ↓ on each header) and the plan stacks in the panel's order, top to bottom. Default: Plants & objects, Lines, Surfaces, Outlines (Outlines last; changed after the user saw the panel). Saved with the plan as `sectionOrder`.
- **Plants stack automatically by type, then size** (markers, objects, perennials/grasses/ground covers, shrubs, trees; larger spread below smaller). No manual override.
- Out of scope: tapping that follows the section order, reordering rows inside Lines and Plants & objects.

## Build rulings
- `SymbolLayer.ordered()` sorts on demand, no cache (a few dozen symbols; `placed` is reassigned from outside, so a cache would risk going stale).
- The Plot plan (PDF) block moved out of the Outlines group body to the bottom of Layers, so moving or collapsing Outlines no longer carries it along.
- Feature labels are part of the outlines block, so they sit under plants by default.
- Existing plans show plants above outlines after this change (the intent).

## Consolidation (review of all the changes)
- Loose numbers moved to the token files (`overlay-tokens.ts`: HIT.line / HIT.symbol, GESTURE.doubleTapPx / draftGap, LABEL, DRAWN); the Figma scale has its own module; the move buttons use `--control-sm`; the draft line is dashed (`--dash-guide`) as its token says.
- One Layers sections component (`layers-sections.ts`) replaces four hand-written headers; one search-picker component (`ui.ts`) serves the Lines and Plants & objects pickers; the tool shares its eye-toggle and nudge code between symbols and lines; `formatLengthFt` lives with the other formatters.
- `base` is only valid under the key `fill`; a marker's card says Direction and Point; an empty file was removed.
