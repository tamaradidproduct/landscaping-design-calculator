# Layering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plants & objects on top by default, the four Layers sections movable up and down (the plan stacks in that order), and plants stacked automatically by type then size.

**Architecture:** A saved `sectionOrder` (pure helpers in `sections.ts`) drives both the panel's block order and `OutlineTool.render`, which now builds one markup block per group and joins them bottom to top. Symbol stacking is a pure `tierOf` plus a sort inside `SymbolLayer.ordered()`, so the renderer, hit test and layer rows all follow it.

**Tech Stack:** TypeScript, Vite, vitest, Playwright checks (`?store=memory`).

**Spec:** `docs/superpowers/specs/2026-10-19-layering-design.md`

All commands run in `plan-builder/`. Never push, open a PR or enable auto-merge (project CLAUDE.md).

## Global Constraints

- **Groups:** `symbols` (Plants & objects), `outlines`, `lines`, `surfaces`. **Default order, top to bottom:** `['symbols', 'lines', 'surfaces', 'outlines']` (changed after review).
- **`sectionOrder`:** optional, a permutation of the four groups; duplicates, a missing or unknown group = invalid plan; absent = default; `v: 1` kept; saved and loaded with the plan; not an undo step.
- **Paint:** bottom to top = the reverse of `sectionOrder`; handles, hover highlights, guides and snap marks stay on top of everything. What cuts what (`visibleShapes`) is unchanged. Tap priority is unchanged (symbols, lines, zones/outlines).
- **Plant stacking, bottom to top:** tier 1 utility markers, 2 objects, 3 perennials / ground covers / ornamental grasses / other, 4 shrubs (accent, privacy, large), 5 trees (evergreen, deciduous, accent). Within a tier a **larger mature spread is below a smaller one**; equal sizes keep placing order (id number).
- **Ids:** symbols keep `y1…` and new ones still go past the highest; stacking never depends on the id except as the last tiebreak.
- **Commits** end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- A plan saved before this change (no `sectionOrder`) opens with Plants & objects above Outlines and paints the same otherwise; an invalid `sectionOrder` is rejected, not crashed on.
- The render refactor keeps handles, hover edge highlights, the fixed-end mark, round handle, labels and guides exactly where they were, and a layer being drawn is still visible whatever the section order.
- Hit-testing a symbol picks the topmost by the new stacking (a tree over a perennial under the same point), also for a rotated object, and stepping through a kind in the Layers rows still works.
- Moving a section while a line draft, a symbol placing, or an outline draw is active leaves no stuck state.
- Section order survives save, close and reopen, and a cloud store round trip (`editorFields` writes and clears it).
